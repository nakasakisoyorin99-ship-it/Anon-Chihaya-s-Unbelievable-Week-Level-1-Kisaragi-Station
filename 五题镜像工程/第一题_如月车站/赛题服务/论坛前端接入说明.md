# 第一题论坛前端与独立调试服务

## 独立预览端口

论坛调试服务使用端口 `60042`，根路径直接打开论坛，不必先进入视觉小说或推进到指定场景。在项目根目录运行：

```powershell
$env:PORT = '60042'
$env:HOST = '127.0.0.1'
$env:FORUM_DEV_MODE = '1'
node '五题镜像工程\第一题_如月车站\赛题服务\服务端源码\论坛服务.mjs'
```

访问 [http://127.0.0.1:60042/](http://127.0.0.1:60042/) 进入论坛；根路径 `/` 即论坛首页。该模式下页面的“返回游戏”链接会打开 `/game`。直接打开 `http://127.0.0.1:60042/forum/` 也可访问论坛。

同一服务的另一个端口可承载完整视觉小说，根路径仍为游戏首页。例如：

```powershell
$env:PORT = '60041'
$env:HOST = '127.0.0.1'
$env:FORUM_DEV_MODE = '0'
node '五题镜像工程\第一题_如月车站\赛题服务\服务端源码\论坛服务.mjs'
```

游戏中的论坛入口位于右下角“论坛调查”。论坛服务同时提供前端 API，因此不要用单纯静态文件服务器替代。

## 游戏桥接

剧情脚本可打开论坛、在第四场景触发计时，并监听提交成功事件：

```js
window.MygoForumBridge.open();
window.MygoForumBridge.enableChallenge();
await window.MygoForumBridge.startChallenge();

window.addEventListener('mygo:forum-clue-submitted', event => {
  const { route, notice } = event.detail;
  // route 是返程信息；notice 是服务端验证用 FLAG。
});
```

场景二、三不可调用 `enableChallenge()` 或 `startChallenge()`；四分钟应从场景四事件开始。论坛侧身份升级必须由玩家操作请求完成，不提供可见的“升级管理员”按钮。游戏表单成功只推进剧情；GZCTF 平台判分由玩家另行提交 FLAG 完成。

## GZCTF 部署

比赛容器需监听 `0.0.0.0`，并由 GZCTF 在容器启动时注入 `GZCTF_FLAG`。生产启动示例：

```sh
HOST=0.0.0.0 PORT=60001 NODE_ENV=production node '五题镜像工程/第一题_如月车站/赛题服务/服务端源码/论坛服务.mjs'
```

不要把正式 FLAG 写入镜像构建内容或公开前端资源。服务端只在管理员成功读取 `GET /api/forum/reports/71` 后将动态 FLAG 放入报告响应。游戏故事回执校验相同的环境变量值。

本地非生产开发可使用 `flag{local_demo_only}` 默认值；生产模式没有 `GZCTF_FLAG` 时服务启动失败，避免意外发布静态开发答案。

GZCTF 官方文档说明动态 FLAG 由平台在容器启动时通过 `GZCTF_FLAG` 注入：[动态 Flag](https://gzctf.gzti.me/guide/features/dynamic-flag)、[快速开始](https://gzctf.gzti.me/guide/start/quick-start.html)。
